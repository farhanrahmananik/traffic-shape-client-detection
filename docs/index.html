Why the accuracy is not the headline

The random forest reaches an accuracy of … under leave-one-round-out evaluation. A linear model with scaled features reaches …, missing only … traces out of ….

A perfect score is a hypothesis about the measurement rig, not a result. This project has already thrown away one feature for exactly that reason, so the score was interrogated rather than celebrated.

The evidence that the task is genuinely easy, rather than leaking: removing any single feature family leaves the forest at the same accuracy. Without the size family it scores …; without the timing family, …; without the burst family, …; without the connection family, …. The signal is redundant: several families would do the job alone.

The clearest single illustration is the count of connections the client opens. On its own — one feature out of … — it reaches …. Firefox opens several connections in parallel for one page load; wget uses one, sequentially. That is what a browser does and a sequential fetcher does not, and it is visible without decrypting anything.

All of the linear model's errors are the automated client mistaken for the browser. The forest misclassified … traces in that direction and … in the other — no page misclassified at all.

Method — five decisions that shaped the data

Each of these was a choice about what to measure. Every one of them could have produced a higher number by measuring something easier.

A perfect feature, measured and removed

Done
Connection-teardown counts — FIN and RST packets — were implemented, measured across a full round, and then deleted. Every Firefox trace had none of either; every wget trace had at least one of each. No exceptions.
Rejected
Keeping a feature that separated the classes perfectly. It was not measuring the clients: wget exits by itself, so its teardown falls inside the capture window, while Firefox is killed only after the capture has already stopped. The feature measured how the harness stops each client.
Without it
It would have sat at the top of the attribution plots, explaining the model with a statement that is false. This one was harder to catch than an obviously broken feature, because connection teardown sounds like it belongs.

Split by capture round, never randomly

Done
… on …, giving … folds. Each round is predicted by a model that never saw it.
Rejected
A random split. Traces from one round share their conditions — the same machine state, the same afternoon — so a random split scores the model on conditions it has already seen.
Without it
The failure is invisible in the output: a leaked split produces a better number, not a worse one, and nothing downstream complains. There is exactly one splitter in the codebase, and the attribution analysis reuses it rather than writing its own.

Filtered capture, headers only, no padding

Done
tcpdump with the filter … on interface …, snaplen … bytes. That keeps the IP and TCP headers and discards the payload, so no page content is ever written to a capture file.
Rejected
An unfiltered capture, full payload storage, and a fixed number of seconds of silence padded onto each end of every trace. All three were flaws in an earlier version of this work, and are the reason it was rebuilt.
Without it
Padding is a constant added to both classes: pure noise at best, and a learnable artefact at worst. A trace ends when the capture goes quiet instead, after … seconds with no new packet.

Per-page fingerprinting not attempted

Done
One question only: which client produced this trace. Every page appears in every round, and therefore on both sides of every fold — by design.
Rejected
Identifying which page was loaded. … classes with a handful of samples each is not a trainable problem, and attempting it would have produced numbers that mean nothing.
Without it
The same page on both sides of a fold is exactly what forces the model to find the difference between the two clients rather than between two pages. Grouping by page instead would answer a different question and quietly change what the accuracy means.

Network isolation, verified every round

Done
Every round captured inside a network namespace with loopback only — … — with the isolation probed before any trace was recorded.
Rejected
Trusting that rewriting the mirrored site had removed every outbound reference. It provably had not: the mirror stores the site's own JavaScript, and link rewriting cannot reach inside it.
Without it
A browser page load fetched analytics from the live site. That traffic does not appear in a capture filtered to the local server, but the DNS, connect and TLS time it costs lands inside the browser's inter-arrival times — and the automated client runs no JavaScript, so the cost falls on one class only.

The shipped tool

One command takes a capture file and returns a verdict. JSON goes to standard output and nothing else does; every diagnostic goes to standard error, so the tool pipes into another program without the caller having to filter anything first. On any failure standard output is left completely empty — a half-written JSON object would be worse than none, because a consuming pipeline would not notice it.

The exit code answers did the tool work and never what did it find: 0 a verdict was produced, 2 a usage error, 3 the capture could not be classified. The predicted class is never an exit code. Overloading it would make tsd-classify x.pcap || echo failed report failure whenever the correct answer happened to be the automated client — a right answer treated as an error.

What the model actually uses

Attributions were computed per fold, on the held-out round only, over … traces. A positive value pushes the prediction toward …, the automated client; the class order is read from the fitted model rather than assumed. Explaining a model on data it was fitted on would reintroduce, in the explanation, the very leak the round-based split prevents in the evaluation — and it would look tidier, not worse.

Reproducibility

The mirrored site content and the packet captures are not published. The pages belong to the university they were mirrored from, and the captures derive from them. What is published instead is a manifest of hashes: anyone re-running the scraper can check they obtained the same corpus without either side distributing a byte of that content.

The shipped tool computes the same numbers

The command-line tool that classifies a capture must produce the same features the model was trained on. Drift there would be silent: the tool would emit a confident verdict built from slightly different numbers, and the only symptom would be worse performance in the field than the published evaluation promised.

So it is checked rather than assumed. … captures were re-processed through the shipped inference path and compared, feature by feature, with the rows the training path had already recorded: … traces × … features = … comparisons, of which … traces agreed on every feature.

This is a parity check and not an evaluation: the shipped model was fitted on every round, so each of those captures is a training row for it, and any accuracy figure from this comparison would measure only how well a model reproduces what it has already seen. No accuracy is computed there.

Limitations

These are not caveats in small print. Each one bounds what the measured numbers above are entitled to claim.

Loopback is not the wire

Everything was captured over the loopback interface, where the round-trip time is a small fraction of a millisecond. The inter-arrival features therefore measure client-side processing time, not network latency — and those are the features the model leans on hardest. The results characterise client behaviour under ideal local conditions and do not transfer directly to captures taken across a real network.

The same environment distorts the size features from the other direction: the kernel batches writes on loopback, so the captures contain single recorded packets far larger than any real network frame. This affects both clients equally and is not a difference the model could exploit, but it means the size and burst features describe application-level write behaviour rather than wire-level packet structure.

The rounds are not fully independent

The four rounds carry the local dates …, …, … and …. The first two are the same day, about ten hours apart, so they are not the independent conditions a round is supposed to represent.

The evaluation is unaffected — no round appears on both sides of a fold, and the split is honest — but two of the folds hold out conditions nearly identical to each other. The fourth round was captured on a genuinely different day, after a restart, precisely so that the question could be answered by comparison rather than admitted and left.

One site, two clients

The corpus is … pages from a single university website, loaded by exactly two clients. Nothing here shows that the same features separate a different browser from a different scraper, or that they survive a site with a different structure. The claim is bounded by the corpus.

A small asymmetry also remains in the data itself. The teardown packets described above were dropped as features, but the packets are still present in the automated client's traces and still contribute to the size, count and burst statistics. Removing them would mean discarding packets under an arbitrary rule — a heavier intervention than the problem warrants, and stated here rather than quietly carried.

The end of a trace is a judgement

A page load is over when the capture goes quiet for … seconds. That threshold is a modelling choice, not a fact about the traffic, and it is recorded in every round's metadata for that reason.

It does not pad the traces: the wait is wall-clock only and the recorded page loads finished far sooner, so the quiet period sits outside the span of the packet timestamps rather than inside it. The earlier version of this work padded every trace at both ends, which is one of the three flaws that caused it to be rebuilt.

Why I built it

I am an M.Sc. Cyber Security student at BTU Cottbus-Senftenberg, RHCSA and RHCE certified, targeting SOC Analyst and system or cloud administration roles in Germany. This problem in particular because deciding what a client is from traffic shape alone, without reading payload, is the signal behind bot detection, scraper detection and command-and-control beaconing analysis — SOC work, not an academic exercise.

It is also a deliberate rebuild. An earlier version of this corpus existed as university work, and its captures had three flaws: tcpdump ran unfiltered, full payload was stored, and every trace was padded at both ends. Removing those three was the point of doing it again, and the capture settings shown above — the filter, the snaplen and the quiet threshold — are what replaced them.
